# Tarn 操作指南：给 Lin 看

这份指南介绍如何在聊天和操作台里使用 Tarn。给聊天模型上传的版本见 [模型操作指南](tarn-model-guide.md)。

## 谁在判断和整理？

| 操作者 | 知道什么 | 做什么 |
| --- | --- | --- |
| 聊天主模型 | 当前窗口提供给它的对话和召回资料 | 决定记什么、补到哪条记忆、主动调整状态 |
| 后台副 API 模型 | 这次送入的新资料、候选旧记忆和年轮 | 判断重复、进展、替代、关联或冲突，整理当前情况 |
| 你 | 聊天内容及操作台里的记录 | 检查结果，补充事实，修改状态或纠正记录 |

AI 可以通过工具修改状态，你可以在操作台修改；两边操作的是同一份数据。副模型不会自动看见聊天主模型的全部上下文，因此写入时需要把变化说清楚。

自动整理在新写入、追加年轮等操作时触发，不会持续巡查并重整全部旧记忆。整理失败时保留原始写入，因此“写入成功”不一定代表“整理完成”。

## 平时直接在聊天里说就可以

可以这样表达意图，主模型再选择对应工具：

- “记一下，我以后更喜欢这种安排。”——保存新的偏好。
- “这件事后来改了，补到原来的记忆里。”——给已有事件追加进展。
- “事情已经结束了，但这段经历要留着。”——调整为已结束、保留。
- “这条已经被新决定替代了。”——核对来源后更新当前情况或旧记录的状态。
- “这条写错了，实际是……”——纠正原记录。

不必每次亲自操作字段。模型没有实际调用工具、工具返回失败，或者只口头说“记住了”，都不能当作已经保存。

## 操作台里怎么看？

打开目录中的 **Tarn**，进入记忆列表，点开一条记忆。

1. **当前情况**：后台整理出的现状；有整理结果时显示。
2. **原记录**：最初写下的正文，保留事件起点。
3. **年轮**：后续补充和感受，最新的排在前面。
4. **三个状态字段**：可以分别修改，保存后列表会刷新。

如果显示“当前情况待重新整理”，说明旧整理结果已不再对应最新资料，应结合原记录与年轮阅读。看到“待确认”时，先核对冲突来源。

列表和模型预览都可能省略内容。没有在预览里看到，不代表没有记录；补写之前先打开完整详情。

## 三类状态分别是什么意思？

| 字段 | 选项 | 怎么理解 |
| --- | --- | --- |
| 事实状态 | 当前有效、已替代、已过期、待确认 | 这条信息现在是否仍然适用 |
| 事项进度 | 经历／无需处理、待处理、进行中、已结束 | 这是不是一件需要推进的事，进展到哪一步 |
| 保存方式 | 保留、收藏、归档 | 希望怎样保存和使用这段记忆 |

常见例子：

- **普通偏好**：当前有效 + 经历／无需处理 + 保留。
- **已经结束的旅行**：当前有效 + 已结束 + 保留。“旅行发生过”仍然是真的。
- **珍惜的一段经历**：可以收藏，无须把它变成待办。
- **已过截止日的报名事项**：可标记已过期；它的历史仍能保留。
- **同一件事出现相互矛盾的说法**：待确认，等核实后再调整。

“已结束”不等于“已过期”；“收藏”也不会让已过期的事实重新有效。归档保留记录，删除才会移除记录。普通往事无需一律标成“待处理”。

## 新决定怎样替代旧决定？

例如某条记忆最初写“选方案 A”，后来明确改成了方案 B：

- 在同一个事件桶里追加“由 A 改为 B”。
- 自动整理尝试把“当前情况”更新为 B，同时保留原正文和变化经过。
- 这个持续更新的事件桶本身可以仍是“当前有效”。

如果有一条独立旧记录只表达已经失效的方案 A，才需要考虑把那条旧记录标为“已替代”。不要因为发生过一次改动，就把整个持续更新的事件都标为失效。

## 发现问题时怎么办？

| 问题 | 处理方法 |
| --- | --- |
| 看起来没记录新进展 | 先读完整年轮，确认是否只是预览截断 |
| 当前情况不完整 | 补充明确事实；如果年轮已有这些事实，让模型检查整理结果，不重复补写 |
| 原记录本身写错 | 编辑原正文，或让模型先读完整记录再修正 |
| 两条记忆很像 | 对照事件和新增信息；相似度高不等于应该合并 |
| 反思挂错事件 | 根据原文纠正归属；没有相关反思可以留空 |
| 旧记忆很多 | 分批核查；目前不会自动把全库历史重复一次性合并 |

副模型处理的是它收到的候选，不能保证找到所有相关旧记忆。钉选、自我锚点等特殊记录也不属于普通自动合并范围。

## 合并审批与旧桶轮转

Tarn 的“合并审批”页显示候选理由、两个桶及已有向量的余弦相似度。相似度不是重复概率；没有有效向量时显示“暂无”。“查找相似候选”仅比较已有向量，不调用副 API，也不直接改桶，每次最多新增 30 组候选。

点开候选可核对两桶完整正文、年轮、状态和拟合并结果。批准后保留目标桶 ID、正文与状态，将另一桶正文和年轮保留为来源，合并后的当前情况仅去掉完全相同的条目。另一桶保留且退出自动浮现，不删除。可拒绝、暂缓，或在合并后撤销；源桶变动会阻止批准，合并后内容有变动会阻止直接撤销。同一版本的候选不会重复提交，拒绝后有新证据才能重新出现。

现有工具新增参数，不新增工具名：

- `introspection()`（等价于 `introspection(order="oldest_review", limit=3)`）：轮到最久未展示的普通桶，每次 1–5 条；自动记录展示时间，不改变桶的更新时间和活跃度。使用 `offset=0`，不需要翻页或另一次打标工具调用。
- `introspection(order="recent", limit=10)`：明确选择近期回看，可按需翻页。为保留现有聊天缓存，对外工具描述与 schema 暂保留旧文字和默认值；实际省略参数时使用旧桶轮转，以此说明为准。
- `trace(bucket_id="保留桶ID", merge_with="并入桶ID", merge_reason="理由")`：仅提交待审批候选，不合并，不能与状态修改或删除混用。

轮转不包含钉选、受保护、自我锚点、归档及已失效等退出整理范围的桶。“已轮到回看”只表示已经提供给模型，不等于模型确认完成检查。轻量 keep alive 和自主安排的唤醒会自动递送 3 条（符合条件不足 3 条时按实际数量），普通聊天不递送。同一次唤醒只预留一批，重试不会换成下一批；模型请求返回后记录展示时间。未确认送达的预留在一小时后重新参与轮转，不会被误记为已经检查。固定说明已由 Lin 确认，保存在 `resources/tarn-wake-review.txt`。
