# Tarn 自动整理规则草案（待 Lin 确认；未接入运行）

用途：副 API 模型根据完整记忆内容提出整理建议。下方只有“固定规则”部分拟作为模型提示词，其他部分用于开发和验收。

## 拟使用的固定规则

根据输入的旧正文、年轮和新消息，输出整理建议及依据，标明每项变更对应的来源 ID 或原文片段。

1. 判断新资料与已有记忆的关系：无新增信息的重复、同一事件的新进展、明确替代旧决定、有关联的独立事件，或证据不足的冲突。相似度只用于寻找候选，不足以证明两条记忆应合并。
2. 同一事件的新进展更新当前情况，并保留历史及来源。独立事件不因主题相似而合并。涉及多个话题时分别判断，不将整段对话统一归入某个记忆类型。
3. 明确的新决定可以替代同一事项的旧决定；新的记录时间不能单独证明事实更新。区分事件发生时间和写入时间，区分意向、选择、尝试和已完成行动。没有购买证据时，不把“选择某商品”写成“已经买下”。
4. 结合正文和相关年轮整理当前情况。某条年轮只更新一个细节时，其他仍然有效的细节继续保留。
5. 同一事项证据冲突且没有明确变更依据时，标记待确认并列出双方来源。
6. 分开判断事实有效性、事项进度和保存方式。过去的经历不默认是未解决的问题；结束不等于遗忘。明确截止时间过去后可标记过期，不能仅因记忆变旧而判定喜好或边界失效。
7. reflection 只保留已有且能对应具体事件的模型反思，并绑定来源。没有相关反思时允许为空；无关的反思不能挂在当前事件下，也不能为了填满结构而生成感受。
8. 短记忆直接保留正文，不另写重复的 moment；长记忆按需要提取片段并标明来源。

## 工程实现

- 应用层读取完整桶及相关来源后再调用整理模型；预览文本不作为整理输入。校验输出的来源引用能对应输入内容。
- 写入前检查记忆版本，出现并发修改则重新读取；正文、当前视图与索引保持版本一致。
- 首先生成可检查的整理建议；未通过结构、来源、版本和冲突检查的结果不写回。
- 保留原始正文、年轮和变更记录，支持回退。注入上下文时对当前情况、摘要和原文片段去重。
- 既有记忆的批量整理不随新代码部署自动执行。删除始终需要 Lin 明确确认。
- 当前情况不代替历史；收藏不绕过失效判定；已结束的经历仍可在相关历史查询中返回。

## 验收场景

- 同一考试的结果与之后报名合成进展，保留各自时间；不会把“可能重考”当作当前状态。
- 商品选择、接线方案、卖家进展分别更新，读取结果包含各自最新有效信息。
- 仅有截断预览时不因没看到更新而补写重复记录。
- 同日的生活事件和阅读反思保持正确对应，不互相继承分类。
- 截止事项不再作为当前待办；收藏的过去经历仍可被相关问题召回。
